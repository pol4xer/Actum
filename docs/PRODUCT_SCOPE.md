# Product scope: Actum MVP

## Главное обещание MVP

Пользователь формулирует цель, указывает измеренную точку старта и доступное время, получает исследованный подневный план и проходит весь цикл внутри Actum:

```text
цель
→ первая попытка за месяц + предел продолжения: 1 / 6 / 12 месяцев
→ web research и строгий plan-v7
→ roadmap на 1 / 6 / 12 циклов
→ 30 календарных миссий текущего цикла
→ встроенные таймеры / счётчики / чек-листы / ответы
→ фактический результат и проверка критерия
→ комментарии и недочёты
→ check-in и игровая награда
→ полный журнал в «Пути»
→ контрольный замер дня 30
→ следующий адаптированный цикл по явной кнопке
```

Для выполнения миссии не нужны блокнот, файл, форма, внешний таймер, другое приложение, самостоятельный поиск или обращение к человеку. Research выполняется до генерации плана, а готовое назначение целиком исполняется клиентом Actum.

## Реализовано

| Слой | Текущая реализация |
|---|---|
| Клиент | Expo SDK 57, React Native, Expo Router |
| Goal intake | Свободная цель, измеренная точка старта, время на день и предел продолжения после первой месячной попытки |
| AI plan | Локальный Node gateway → research → structured JSON plan-v7 |
| Program | Самый ранний обоснованный целевой цикл, roadmap до лимита, ближайшие 30 дней и assessment дня 30 |
| Research | Responses API `web_search`, strict JSON с ранним целевым циклом, URL-цитаты и program-level кэш |
| Исполнение | `timer`, `counter`, `checklist`, `text_log` — только встроенные блоки |
| Проверка | Фактическое время/количество, явный ответ по критерию, комментарии и недочёты |
| Game loop | Миссии, check-in, XP, энергия, серия, свет, buffs/debuffs |
| Журнал | Versioned `MissionRun`, итоговый check-in и полный просмотр в «Пути» |
| Persistence | AsyncStorage на native, localStorage на web, миграции v1/v2→v3, видимый статус записи |
| Potential twin | Игровое сравнение текущего выполнения с принятым планом |
| Notifications | Одно ежедневное локальное напоминание |

## Намеренно простая архитектура

Для локального MVP используются два процесса:

```text
Expo app → http://127.0.0.1:8787/plan → research prompt → OpenAI web_search
                                                   → plan prompt → strict plan-v7 JSON
```

API key находится только в `.env.local` на компьютере и не включается в мобильный bundle. Это ещё не production backend: сервер работает на Mac разработчика и нужен только для создания GPT-плана. После принятия плана вся сессия, проверки и журнал работают локально в приложении без OpenAI.

Research и планирование разделены. Первый Responses-вызов возвращает строгий JSON с практическим брифом, самым ранним обоснованным циклом и URL-цитатами. Планировщик запускается только если этот цикл помещается в retry cap, и обязан вернуть тот же `targetCycleNumber`. Локальный validator проверяет каждый день, goal-linked primary timer/counter, минимальную ежедневную и предконтрольную дозировку растущих числовых целей, roadmap, assessment, baseline-арифметику и отсутствие внешних зависимостей. Checklist, журнал, безопасность, пассивное ожидание или восстановление не могут подменять практику. Ответ преобразуется в доменную модель только после успешной проверки.

Следующий цикл никогда не создаётся автоматически. После Дня 30 пользователь подтверждает записанный результат и нажимает «Собрать месяц N». Новый planning-запрос получает target, roadmap и сводку завершённых циклов, но не получает полный личный журнал. Сохранённый research переиспользуется; если он больше недоступен, gateway не запускает новый web-search без явного нового сценария. Завершённые этапы roadmap остаются неизменными.

Runner хранит абсолютные timestamp таймеров и полный checkpoint после событий. После достижения назначенной отметки рабочий таймер продолжает прямой отсчёт до ручного завершения, чтобы сохранить реальный результат выше плана и при необходимости досрочно закрыть числовую цель. Состояние переживает перезапуск приложения. Быстрые изменения сериализуются в локальное хранилище; при ошибке запись не замалчивается, а приложение показывает блокирующий экран с повтором.

## Что MVP пока не делает

- не работает с AI без запущенного локального proxy;
- не синхронизирует данные между устройствами;
- не имеет аккаунтов, Supabase и удалённой истории;
- не поддерживает несколько одновременных целей;
- не принимает распознанные цели на уменьшение числового показателя: текущий runner умеет честно проверять только достижение «не меньше назначения», поэтому такой запрос блокируется локально до платного AI-вызова;
- не генерирует точные ежедневные задания дальше текущих 30 дней заранее;
- не содержит WidgetKit/App Intents и HealthKit;
- не является медицинским, финансовым или терапевтическим продуктом.

## Практический следующий план

1. Начать новую цель с каждым пределом продолжения и проверить roadmap plan-v7 и targetCycleNumber.
2. DEV-пропусками дойти до Дня 30, выполнить assessment и проверить переход к месяцу 2 без нового web-search.
3. Прогнать 10–15 разных измеримых целей и исправлять prompt/contract только по конкретным неисполняемым назначениям.
4. Пользоваться MVP несколько дней, проверяя возобновление таймера, локальную запись и удобство ежедневного runner.
5. Только после этого вынести `/plan` в маленький backend для TestFlight, затем решать вопрос синхронизации и аккаунтов.

Сейчас задача — доказать, что подробный персональный GPT-план, целиком исполняемый и журналируемый внутри Actum, действительно полезен.
