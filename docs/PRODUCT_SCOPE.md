# Product scope: Actum MVP

## Главное обещание MVP

Пользователь пишет свою цель обычным языком, указывает доступное время и точку старта, получает от GPT конкретный план, принимает его и проходит цикл:

```text
цель
→ GPT-план
→ главы и миссии
→ действие
→ честный check-in
→ награда / последствие
→ recovery
→ следующая миссия
```

Если этот цикл удобен и реально помогает возвращаться к цели, идея подтверждается. Всё остальное пока вторично.

## Реализовано

| Слой | Текущая реализация |
|---|---|
| Клиент | Expo SDK 57, React Native, Expo Router |
| Goal intake | Свободный текст, время на миссию, горизонт, точка старта |
| AI plan | Локальный Node gateway → research → structured JSON |
| Research | Responses API `web_search`, реальные URL-цитаты и быстрый режим без web |
| Fallback | Контролируемые локальные шаблоны, если GPT недоступен |
| Game loop | Миссии, check-in, XP, энергия, серия, свет, buffs/debuffs |
| Recovery | Микро-шаг после пропуска |
| Potential twin | Игровое сравнение текущего выполнения с принятым планом |
| Persistence | AsyncStorage на native, localStorage на web |
| Notifications | Одно ежедневное локальное напоминание |

## Намеренно простая архитектура

Для локального MVP используются два процесса:

```text
Expo app → http://127.0.0.1:8787/plan → research prompt → OpenAI web_search
                                                   → plan prompt → strict JSON
```

API key находится только в `.env.local` на компьютере и не включается в мобильный bundle. Это ещё не production backend: сервер работает на Mac разработчика и нужен только во время тестирования GPT-функции.

Research и планирование разделены. Первый Responses-вызов возвращает фактический бриф и URL-цитаты, второй ограничен JSON-схемой и преобразуется в `Goal`, `PlanVersion`, `QuestChapter` и `Mission`. Миссия может быть ручной или таймерной и содержит видимые шаги. Пользователь сохраняет именно тот план, который увидел на review-экране.

## Что MVP пока не делает

- не запускает многостраничный background-report на десятки минут; web-research ограничен контекстом практического плана;
- не работает с AI без запущенного локального proxy;
- не синхронизирует данные между устройствами;
- не имеет аккаунтов, Supabase и удалённой истории;
- не поддерживает несколько одновременных целей;
- не содержит WidgetKit/App Intents и HealthKit;
- не является медицинским, финансовым или терапевтическим продуктом.

## Практический следующий план

1. Вставить реальный `OPENAI_API_KEY` в `.env.local` и пройти на Simulator сценарий «своя цель → GPT → принять план».
2. Проверить 10–15 разных реальных целей и поправить один prompt/JSON-схему по фактическому качеству планов.
3. Дать MVP пользоваться несколько дней: check-in, пропуск, recovery, перезапуск приложения, уведомление.
4. Только если основной цикл нравится — развернуть тот же `/plan` как маленький удалённый backend для TestFlight.
5. Затем добавить настоящий research-этап и источники, а уже после — Supabase sync и iOS widget.

Иными словами: сейчас задача не строить production-платформу, а доказать, что персональный GPT-план внутри игрового цикла Actum вообще полезен и приятен.
